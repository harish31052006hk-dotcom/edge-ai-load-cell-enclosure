## 1. M2 Objectives & Deliverables

1. **Simultaneous Multi-Class Detection**:
   - Accurately identify and separate `bottom`, `top`, and `enclosure_assembled`.
2. **False Positive & Sub-Part Suppression**:
   - Prevent assembled enclosures from being falsely double-counted as individual loose parts.
3. **Accuracy Verification**:
   - Test detection confidence scores across all physical test scenes.
4. **Metrological Calibration & Verification**:
   - Independent verification using known $32\text{ mm} \times 32\text{ mm}$ physical geometry.
5. **Edge Deployment Readiness**:
   - Document latency trade-offs and future Raspberry Pi 5 optimization pathways.

## Convert and Run Live

The trained YOLO26 Small model is integrated into a real-time computer-vision pipeline using Python, OpenCV, Flask, and Ultralytics.

The live pipeline captures frames from a video camera and passes them to the object-detection model:

$$\text{\bf Camera} \longrightarrow \text{\bf OpenCV Frame Capture} \longrightarrow \text{\bf YOLO Detection} \longrightarrow \text{\bf Bounding Boxes} \longrightarrow \text{\bf Confidence Scores} \longrightarrow \text{\bf Inspection Dashboard}$$

The system continuously classifies and tracks the three target enclosure classes:
- `bottom` (Lower base enclosure component)
- `top` (Upper protective cover)
- `enclosure_assembled` (Mated two-piece enclosure assembly)

The multi-threaded Flask web dashboard ([`src/app.py`](../src/app.py)) provides hardware lifecycle controls (`Start Camera`, `Stop Camera`), an MJPEG live feed, and a real-time detection event log.

## Accuracy Check

The detection capability of the trained model was verified using physical component test scenes on the inspection surface.

The observed individual detection confidences are:
- `enclosure_assembled`: **85.8%** ([`datasets/test_image.jpg`](../datasets/test_image.jpg))
- `bottom`: **78.9%** ([`datasets/bottom.png`](../datasets/bottom.png))
- `top`: **83.1%** ([`datasets/top.png`](../datasets/top.png))
- Separate components ([`datasets/top and bottom.png`](../datasets/top%20and%20bottom.png)):
  - `bottom`: **85.6%**
  - `top`: **72.4%**

> [!IMPORTANT]
> **Academic & Metrological Note on Metrics:**
> These values represent **individual detection confidence scores** for specific physical test images, not statistical model accuracy. In accordance with strict evaluation standards, overall accuracy metrics such as mean Average Precision (mAP@50, mAP@50-95), precision, recall, F1-scores, and confusion matrices are **not claimed or fabricated**, as they require a larger annotated evaluation test split.

## Fair Benchmark

The model was benchmarked on the available development host using CPU-based inference to establish an empirical performance baseline.

- **Cold-Start Latency:** Approximately **7.9 seconds** (initial PyTorch graph loading, weight extraction, and memory mapping)
- **Steady-State Inference Latency:** Approximately **100-140 ms per frame**
- **Effective Throughput:** Approximately **7-10 FPS**
- **Host Platform:** Windows 64-bit Laptop
- **Execution Backend:** CPU-only (`torch 2.15.0+cpu`)
- **Raspberry Pi 5 Status:** **Raspberry Pi 5 was not benchmarked.** No physical Raspberry Pi 5 measurements or claims are made.

## Own Target and Trade-off

The deployment objective is to establish an embedded quality-inspection workstation positioned directly over the mechanical assembly line.

### Current Validated Baseline
- **Model Checkpoint:** PyTorch `weights.pt`
- **Inference Engine:** Windows Host CPU
- **Steady-State Latency:** ~100–140 ms/frame
- **Throughput:** ~7–10 FPS

### Future Target
- **Target Platform:** **Raspberry Pi 5** (ARM64 Cortex-A76)
- **Planned Execution:** Local edge inference with camera module integration
- **Current Status:** Performance, thermal profile, and FPS on Raspberry Pi 5 are **planned for future deployment and not yet benchmarked**.

### Trade-Off Analysis

#### Current CPU Approach
- **Advantages:**
  - Fast, reproducible development environment.
  - Interactive debugging with full desktop inspection windows.
  - Zero dependence on specialized accelerator drivers or toolchains.
- **Limitations:**
  - Current measured throughput is approximately 7-10 FPS on the host CPU.
  - The current implementation depends on a Windows development host.
  - The implementation has not yet been validated on the intended embedded edge platform.

#### Future Edge Deployment (Raspberry Pi 5)
- **Advantages:**
  - Self-contained, compact footprint directly on the inspection stand.
  - Elimination of dedicated PC workstation hardware.
  - Direct GPIO / industrial fieldbus integration capability.
- **Limitations:**
  - Embedded thermal and power limits require model optimization (e.g., export to ONNX or NCNN format).
  - Must be experimentally evaluated and validated on physical hardware prior to production certification.
